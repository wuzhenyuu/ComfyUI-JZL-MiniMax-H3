# 本机 Codex 文本与生图

本插件新增文本服务商 `Codex (本机登录)` 和独立节点 **JZL Codex 生图/改图（本机）**。原有本地 LLM、HTTP API、H3 视频节点及默认选项保持原状；只有明确选择 Codex 或执行新生图节点时才使用该路径。

## 使用前提

- Codex 可选接口读取本机配置需要 **Python 3.11 或更新版本**；原插件的 Python 要求仍为 `>=3.10`，此处不提高原功能的安装要求。
- `custom_nodes` 下同时保留本插件与相邻的 `comfyui-codex-cli-nodes`，后者提供 `codex_runner.py`、`codex_events.py` 执行层。
- 运行 ComfyUI 的同一 Windows 用户已安装可用 Codex CLI，并以官方 ChatGPT 账户登录。可在该用户的终端执行 `codex login status` 检查状态；桌面应用已登录不必然代表 CLI 已确认登录。
- CLI 可由 `PATH` 找到，或通过已有的 `CODEX_CLI_EXE` 指定。使用自定义 `CODEX_HOME` 时应为绝对路径，并指向该用户实际使用的 Codex 配置。
- 本接口使用 Codex 在线服务与账户额度，需要网络。它不会在本机加载 Codex 模型权重，也不承诺免费、无限次数或固定费用。

本 Fork 不分发上述外部执行层，目前也没有可提供的公开自动安装来源，需要自行准备兼容的本机执行层。本文不提供其独立安装承诺；仅安装本 Fork 而未配备该执行层时，Codex 文本、模型目录和生图功能不可用，原接口不受影响。

插件无需新增 API Key，不读取或复制账户令牌到工作流和插件设置。登录凭据仍由 Codex 自身管理。此入口只支持官方 ChatGPT 登录；本机若选择其他或自定义 provider，会明确报错。

## 文本：两个独立设置入口

**LLM-API 设置节点**：打开 API 设置，在服务商中选择 `Codex (本机登录)`，选择 Codex 模型、调整专用设置并保存。原来接入该设置节点的文本处理链路即可使用 Codex。

**短剧管理器/导演台**：在文本增强的 LLM 设置中选择 `在线API [api]`，再将服务商选为 `Codex (本机登录)`，保存该管理器节点设置。这里沿用管理器自己的工作流配置，不会自动改写另一个 API 设置节点。

两个入口均提供以下 Codex 专用字段：

| 字段 | 含义 |
|---|---|
| Codex 模型 | 自动识别本机 CLI 返回的模型目录后下拉选择；“使用本机 Codex 默认模型”保存为空值，执行时继承本机配置。账户必须实际支持所选模型。 |
| 推理强度 | 默认 `high`，可选 `low`、`medium`、`high`、`xhigh`；留空继承本机配置。 |
| 超时（秒） | 默认 `1800`，允许 `1` 至 `86400`；超时终止本次等待，不代表任务完成。 |

选择 Codex 后，普通 HTTP 的模型名、API Key、Base URL、temperature、Token 上限与 DeepSeek 思考开关不适用于该调用。切回原服务商可继续使用原设置；Codex 失败不会自动回退到它们。

两个文本配置入口共用 `GET /jzl/codex/models`。识别时只调用本机 `codex app-server` 的 `initialize`、`model/list`，不启动文本或图片生成任务；适配代码不读取 `auth.json`，登录由 CLI 自身管理。界面显示识别数量和北京时间，可点“重新识别”强制刷新；普通读取共享 60 秒的内存目录缓存，不使用写死的模型名单，也不把旧的 `models_cache.json` 直接当本次目录结果。Codex 自身可能对目录使用缓存，因此“目录可选”不代表每个模型均已经实际调用验收。

目录获取失败时显示错误，保留本机默认和已有保存值；已保存但不在目录中的模型会标为“已保存，当前未识别”，不会自动换成第一个模型。仅选择 Codex 才触发目录识别，原 HTTP 服务商不会因此启动 CLI。识别失败不阻止保留原值，真正执行时仍以 CLI 的返回为准。

每次真正执行的 Codex 调用均为独立临时任务，不继承上一轮对话。插件不会在失败后自动再次提交模型任务；检查原因后再手动重试，避免无意重复使用额度。

## 图片：独立生图/改图节点

在节点菜单 `JZL/Codex` 下添加 **JZL Codex 生图/改图（本机）**，节点 ID 为 `JZL_CodexImageGenerate`。

1. 填写提示词；需要的数量、画幅、尺寸、透明背景和其他要求均写在提示词中。
2. 文生图不连接参考图；改图连接一张参考，多参考则连接多个动态参考端口。
3. Codex 模型、推理强度、超时使用与上表相同的约定。
4. 将 `图像` 输出接到原生 **SaveImage / 保存图像**，然后排队执行。

提示词原文会交给适配层。节点不提供伪装为生效的 seed、硬尺寸或 temperature 控件；提示词里的数量与尺寸属于模型请求，实际生成数量、像素尺寸和内容质量以返回文件为准。

参考图按端口数字顺序处理，例如 `reference_image_2` 先于 `reference_image_10`。每个端口若接入 IMAGE batch，会依次展开其中每张图。参考图以原始像素尺寸分别存为本次临时 PNG，不叠成联系表，不缩到 H3 参考尺寸，也不套用 H3 的 9 图上限。动态端口受 ComfyUI 框架最多 100 个端口的限制；这不代表账户或实际图片模型承诺支持 100 张参考。

输出说明：

| 输出 | 内容 |
|---|---|
| 图像 | IMAGE 列表；每项为原生尺寸的 `[1,H,W,3]`、CPU `float32`、0–1 RGB 图。不同尺寸不会为拼 batch 而缩放。 |
| 透明遮罩 | 与图像顺序一致的 MASK 列表 `[1,H,W]`；有 alpha 时为 `1-alpha`，无 alpha 时为全零。 |
| 生成信息 | JSON 字符串，含实际文件路径、尺寸、是否有 alpha、参考数量与请求配置；不虚构剩余额度或模型完成承诺。 |

原生 SaveImage 可接收列表并逐张保存。RGB IMAGE 与 MASK 分开传递；需要透明合成时应同时使用 MASK。Codex 返回的原始透明文件会保留在本次结果目录中。

每次执行输出到 ComfyUI 的以下独立目录，文件夹时间使用北京时间：

```text
output/jzl/codex/YYYY-MM-DD_HHmmss_<UUID>/
```

节点只接收本次 Codex 线程中可验证且能够真实解码的图片；只有文字回复不算生图成功。返回的多张图全部保留。临时参考 PNG 在本次调用结束后清理，Codex 原缓存、用户原始图片与结果目录不会被这项输入清理删除。

图片节点每次重新排队执行都会发起新请求，不复用上一次图片结果，也不自动重试。多次点击排队可能产生多次账户额度消耗。

## 错误与取消

- 缺少相邻执行层：恢复 `comfyui-codex-cli-nodes` 依赖，确认相关文件存在。
- CLI 找不到或未确认登录：检查同一 Windows 用户的 `PATH`、`CODEX_CLI_EXE` 和 `codex login status`。
- 模型不兼容、能力未开放、额度或速率受限：检查本机模型选择和账户实际权限；节点不会换供应商绕过错误。
- 超时或网络错误：确认网络与任务状态后，按需调整超时并手动提交；超时不等于图片已经生成。
- 未返回图片、文件损坏或无法确认本次来源：本次任务报错，不以文字、旧缓存或原始参考图充当生成结果。Codex 原缓存仍保留，便于检查。

节点使用 ComfyUI 中断信号，取消异常不会被吞掉。当前复用执行层的终止行为只覆盖根进程；整棵子进程树的取消与远端任务是否同步停止尚未验收，不能据此保证取消后立即停止所有后台工作或额度使用。遇到持续运行应先检查本次 CLI 进程与账户任务状态，避免立即重复提交。

## 验证边界

离线 mock 与 schema 检查只能证明节点输入输出、图片解码和错误分支等本地契约。真实文本模型、真实图片生成、账户权限、实际原生分辨率和输出质量需要在目标环境分别验证；mock 通过不代表真实模型已验收。
